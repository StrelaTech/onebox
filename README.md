# OneBox

**Всё, что нужно для вашего VPN-подключения — в одном приложении.**

[![License: GPL-3.0](https://img.shields.io/badge/License-GPL--3.0-blue.svg)](LICENSE)

</div>

OneBox — бесплатное приложение для Android, которое подключает вас к VPN
через ядро [xray-core](https://github.com/XTLS/Xray-core). Вставьте ссылку на
подписку от вашего VPN-провайдера — и приложение само получит список серверов,
покажет их списком и подключит вас одним нажатием.

## Возможности

- 📥 **Удобный импорт подписок** — вставьте ссылку в приложение, и OneBox
  скачает список серверов. Подписка обновляется автоматически.
- 🔗 **Умеет читать самые разные ссылки** — `vless://`, `vmess://`,
  `trojan://`, `ss://`, обычные тексты и Base64-строку, а также готовый
  JSON-конфиг.
- 🚀 **Подключение одним нажатием** — выберите сервер на экране и нажмите
  «Подключить». Останавливать/запускать ядро заново не нужно.
- 📊 **Информация о подписке** — приложение показывает срок действия
  подписки и сколько трафика осталось.
- 🌍 **Использует geoip/geosite-данные** — распаковываются автоматически при
  первом запуске, ничего скачивать вручную не нужно.
- 🎨 **Современный интерфейс** — чистый Jetpack Compose (Compose
  Foundation + собственный дизайн-кит, без Material и Miuix).

## Поддерживаемые протоколы

**VLESS**, **VMess**, **Trojan**, **Shadowsocks**, а также SOCKS/HTTP в
качестве транспорта.

## Как начать пользоваться

1. **Установите приложение.** Скачайте последний APK со
   [страницы Releases](https://github.com/StrelaTech/onebox/releases)
   и установите его (потребуется разрешение «Установить из неизвестных
   источников»). Нужен Android 7.0 или новее.
2. **Добавьте подписку.** Откройте вкладку «Серверы» → «Добавить
   подписку» и вставьте ссылку, которую дал вам VPN-провайдер. Если подписки
   нет — можно вставить отдельную ссылку на сервер (`vless://…`) или
   содержимое JSON-конфига: приложение само определит формат.
3. **Выберите сервер и подключитесь.** На вкладке «Подключение» нажмите
   кнопку подключения и подтвердите запрос Android на создание VPN-соединения
   — это стандартный диалог системы, OneBox ничего не делает в фоне без вас.

Список серверов берётся из подписки; активный сервер можно менять в любой
момент.

# Для разработчиков

## Структура проекта

| Модуль    | Тип              | Назначение                                                        |
|-----------|------------------|-------------------------------------------------------------------|
| `app`     | application      | Точка входа (`MainActivity`), иконки, манифест, подпись релиза     |
| `ui`      | library          | Compose-интерфейс: экраны, компоненты, тема, собственный дизайн-кит |
| `core`    | library          | Чистая логика: парсинг ссылок/подписок, сборка JSON-конфига ядра, i18n-строки |
| `data`    | library          | Хранилища (SharedPreferences), загрузка подписок (OkHttp), use-case'ы |
| `engine`  | library          | `TunVpnService`, обёртка `XrayController`, управление гео-файлами   |
| `xray`    | Go-модуль        | Обёртка над xray-core, собирается в `xray.aar` скриптом внизу       |

Зависимости модулей: `app → ui → engine → data → core`; `engine` подключает
нативный `xray.aar`.

Ядро собирается из Go-кода в `xray.aar` с помощью `gomobile bind` и работает
внутри приложения поверх `tun`-интерфейса (`VpnService`).

## Требования

- **JDK 25** — сборка. Unit-тесты `core` автоматически используют JDK 21 через
  Gradle toolchain (Robolectric 4.17 не работает на Java 25)
- **Android SDK**: `platforms;android-37.0`, `build-tools;36.0.0`
- **Android NDK**: `29.0.14206865`
- **Go**: `1.27.1`, `gomobile` (устанавливается скриптом при необходимости)

## Сборка

```bash
# 1. Собрать xray.aar и опубликовать в локальный Maven-репозиторий
#    (делается один раз, повторно — при изменениях в Go-коде)
./scripts/build-xray-aar.sh

# 2. Отладочный APK
./gradlew assembleDebug

# 3. Тесты и линт
./gradlew testDebugUnitTest lintDebug

# 4. Подписанный релиз (нужен keystore.properties, см. ниже)
./gradlew assembleRelease bundleRelease
```

Артефакты: `app/build/outputs/apk/release/*.apk`,
`app/build/outputs/bundle/release/*.aab`.

> **Почему `xray.aar` не кладётся в модуль `engine` напрямую?** `engine` —
> библиотечный модуль, а AGP не разрешает библиотеке подключать локальный
> `.aar`. Поэтому AAR публикуется в локальный Maven-репозиторий
> `local-maven/` через `scripts/build-xray-aar.sh` и подключается как
> обычная зависимость `xray:xray:1.0.0@aar`. Каталог `local-maven/` в git
> не хранится.

## Подпись

Релиз подписывается keystore-файлом, данные передаются через
`keystore.properties` в корне (файл не входит в git):

```properties
storeFile=onebox-release.jks
storePassword=...
keyAlias=onebox
keyPassword=...
```

Сам `*.jks` / `*.keystore` в репозиторий не коммится. Без
`keystore.properties` сборка `release` пойдёт без подписи (unsigned).

## Релизы

GitHub Actions не используется — релизы собираются локально и вручную:

1. Обновите `versionName` / `versionCode` в [`app/build.gradle.kts`](app/build.gradle.kts).
   Версия `X.Y.Z` соответствует `versionCode = X*10000 + Y*100 + Z`
   (например, `26.0.1-alpha` → `260001`).
2. Соберите `assembleRelease` (и при необходимости `bundleRelease`).
3. Готовые артефакты скопируйте в `dist/`, переименовав в формате
   `OneBox-<версия>.apk` / `.aab`, снимите контрольные суммы
   (`sha256sum … > SHA256SUMS.txt`) и приложите к Release на GitHub.

Маппинги для смотра обфускации лежат в
`app/build/outputs/mapping/release/mapping.txt` — сохраняйте их для каждой
версии, чтобы можно было разбирать краши.
